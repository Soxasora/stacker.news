# Total migration: Bootstrap + react-bootstrap → Tailwind CSS v4 + Base UI

## Context

stacker.news is a Next.js (pages router) app styled with Bootstrap 5.3.8 + react-bootstrap 2.10.10 + SCSS. Goal: remove both completely, rebuild components on **@base-ui/react 1.6.0** (NOT preinstalled — installed in PR2 commit 0; the old `@base-ui-components/react` package name is dead) styled with **Tailwind CSS v4.3.1**. **Strategy revised 2026-07-06 (was: pixel-identical to master)** — behavior parity stays binding; visual parity does not. Components are built with **native Tailwind/Base UI solutions at nearest-native values**, with SN's identity carried by a small `@theme` brand block instead of value-exact Bootstrap replication (see §Strategy revision below). Dark mode, territory runtime branding (CSS-var overrides from `lib/domains/custom-css.js`), and all interaction behavior must survive unchanged.

Current state of `redesign-tailwind`: at master HEAD, zero migration code — only the audit doc (`docs/dev/bootstrap-usage-audit.md`: 160 distinct utility classes / 1527 uses; **undercounted — `wallets/` adds ~100+ more uses and `groupClassName`-style props carry another 69**) and a form-system sketch (`components/form/base-ui-transformation.md`).

**Decided with user:** 3 PRs — ① Tailwind parity, ② Base UI components, ③ Bootstrap removal. Latest versions of everything. Token rename `--bs-*`/`--theme-*` → `--sn-*` and `data-bs-theme` → `data-theme`. The 63 `.module.css` files stay (var re-point only); Tailwind-ify opportunistically later. PR2 components use **hybrid styling** — module.css for stateful skins/variants, Tailwind for layout (keystone 6).

## Strategy revision (2026-07-06) — native-first, no pixel parity

Decided with sox after C2's first four components landed with "ugly tw values" (arbitrary brackets replicating compiled Bootstrap). The revision, in one sentence: **stop replicating Bootstrap's compiled output; use the nearest native Tailwind/Base UI solution, and express SN's identity as `@theme` tokens rather than per-site arbitrary values.**

Locked decisions:
1. **Hybrid styling stays** (keystone 6 survives) — module.css keeps owning variant skins/state/popup chrome via `var(--sn-*)`; what changes is the *values* rule: recipes and skins use native-scale classes or brand tokens, never arbitrary brackets (deliberate SN one-offs like the alert border-radius excepted). Sass-exactness is no longer owed anywhere — nearest-native wins, judged by eye.
2. **Type identity via token, not brackets** — `@theme` gets `--text-base: .93rem` + `--text-base--line-height: 1.75` (body/fs-6 identity; grep for pre-existing `text-base` uses before landing — expected 0). Everything else snaps to the stock scale: fs-5 sites → `text-lg`, RFS heading clamps → plain `text-*` steps at PR3.
3. **Subtle native motion adopted** (keystone 5 rewritten below) — snap was a parity artifact, not a design choice.
4. **Radius simplifies to stock** — `rounded-sn` (.4rem) → `rounded-md` (.375rem, imperceptible); drop the token + its `lib/cn.js` classGroups entry.
5. **Container drops the Bootstrap tiers** — single `max-w-4xl` (896px ≈ today's 900px cap); tablets gain a little width between 576–992px, accepted.

What this deletes from the plan: all arbitrary bracket values outside true one-offs; the obligation to verify values against compiled sass; PR3's computed-style-dump-as-contract (dump stays as *reference*); the ≤0.1% pixel-diff gate (harness stays as a review aid); the post-migration "tokenize arbitrary values" cleanup (moot). What it does NOT touch: the coexistence cascade (keystone 1 — the `important` flag is about out-shouting Bootstrap while both load, not parity), the `--sn-*` bridge, wrappers/APIs, the C-commit order, deviations D1–D10, and the entire interaction-parity checklist.

Migration debt created: a **C2.5 native-value rework** (tracked in the PR2 doc §0) — rework Button/Badge/Alert/Container recipes + a small tree sweep (`text-[0.93rem]`→`text-base` ×12, `text-[1.1625rem]`→`text-lg` ×9, `font-[monospace]`→`font-mono` ×29, `rounded-sn`→`rounded-md` ×~13, drop the seven `ms-[0.1rem]` badge parity-nudges), and update `scripts/codemods/bs-tw-map.js` entries to match so a re-run can't reintroduce old spellings.

## Architecture keystones (apply to all 3 PRs)

1. **Cascade-layer coexistence.** Bootstrap CSS is unlayered with `!important` utilities. Tailwind utilities import with the `important` flag: *layered `!important` > unlayered `!important` > unlayered normal > layered normal* (CSS Cascade 5). This reproduces Bootstrap's "utilities always win" contract during coexistence. **Keep the flag through PR3 and its parity gate** — dropping it *alone* would flip every utility-vs-module conflict. But it is scheduled debt, not permanent architecture (revised 2026-07-05 after PR2 §11.0 exposed its failure mode against consumer module skins): the post-migration **cascade de-escalation** cleanup drops it *paired* with wrapping module skins in `@layer components`, which preserves the utilities-win contract without any `!important`.
2. **Alias-flip token bridge.** PR1: `--sn-primary: var(--bs-primary)` etc. (aliases point at live Bootstrap vars, so territory branding + dark mode work untouched). PR3 flips direction: `--sn-*` become canonical literals, `custom-css.js` emits `--sn-*`, everything else renames mechanically.
3. **Dual theme attribute.** PR1 makes the `_document.js` init script + `dark-mode.js` set BOTH `data-bs-theme` and `data-theme`. PR3 drops the `bs` one.
4. **Wrappers keep their public APIs.** `useShowModal` (21 files), `useToast` (34), `form.js` exports (~100 consumers), `ActionDropdown` (13) — internals swap, consumers don't move. New compound components mirror react-bootstrap prop shapes (`variant`, `size`, `as`→`render`) so consumer diffs are import-line swaps.
5. **Subtle native motion (revised 2026-07-06; was "no animations").** Master snaps only because Bootstrap compiled with `$enable-transitions: false` — a parity artifact. New popups (menu, tooltip, popover, dialog, drawer, collapsible) adopt Base UI's native pattern: ~150ms ease-out fade (+slight scale where the Base UI docs examples use it) via `data-starting-style`/`data-ending-style` CSS in the popup chrome modules, disabled under `@media (prefers-reduced-motion: reduce)`. Toast slide/progress keeps its existing keyframes; Drawer's 450ms default is shortened to match the ~150ms family, not zeroed.
6. **Hybrid styling split (PR2+).** Module CSS answers *"what does this component look like in each of its states"*: variant skins (`data-variant` + CSS-var indirection), state styling via Base UI data attributes (`[data-highlighted]`, `[data-popup-open]`, `[data-disabled]`…), popup chrome/shadows/z-index, the surviving animations. Tailwind answers *"how is this instance arranged on the page"*: layout, spacing, flex composition, and all consumer `className` overrides — which always win, because utilities are layered-`important` and modules are unlayered normal (keystone 1). Safety rules: **(a) one property, one source, per component** — `twMerge` is blind to module classes, so never declare the same property in both the module skin and the recipe's utility string; **(b) modules stay unlayered until the post-PR3 cascade de-escalation** — layering them (or dropping the utility `important` flag) *on its own* flips the override contract; the two moves only work as a pair (see post-migration cleanups); **(c) new modules theme via `var(--sn-*)` only** (aliases live since PR1) — dark mode and territory retint flow through with zero `[data-theme=dark]` selectors, and the PR3 rename sweep never touches these files. Button (mapping table) is the template. **(d, added 2026-07-06)** Values rule: recipe utility strings and new module declarations use native-scale classes or brand tokens only — no arbitrary bracket values except deliberate SN one-offs (e.g. the alert border-radius). Nearest-native supersedes value-exact everywhere.
